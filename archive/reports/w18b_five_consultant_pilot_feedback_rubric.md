# W18B Five-Consultant Pilot Feedback Rubric

Decision: COMPLETE / CREATE STILL DISABLED

## Objective

Turn the next screenshot and five-consultant pilot pass into a structured feedback loop.

## Goal

Five consultants should be able to set up a prospect, run IDB, review records, value sell, guide the demo, export evidence, and reset without confusion.

## Pilot Roles

- Consultant UX Director Agent: watches first-viewport clarity, scroll depth, and action wording.
- Pilot Enablement Agent: runs the five-consultant checklist and captures pass/fail evidence.
- Storytelling Agent: evaluates whether the story helps the consultant open, prove, handle objections, and close.
- ROI / Competitive Agent: evaluates whether ROI and competitive summaries are usable live.
- SuiteScript Write Agent: verifies write-readiness language is accurate and does not imply live writes are enabled.
- Validation And Evidence Agent: confirms trace export, packet export, and reset behavior.

## Feedback Rubric

Score each category from 1 to 5.

1 means blocked or confusing. 3 means usable with coaching. 5 means consultant-ready.

| Area | What To Check | Passing Evidence |
| --- | --- | --- |
| Plan first viewport | Guided Intake is the first useful Plan surface. | Consultant can enter customer, website, and notes without scrolling past expanded Story Bar. |
| Lane confidence | Recommended lane explains website-first signal and does not overfit notes. | Consultant understands why lane was chosen and can override if needed. |
| Review clarity | Execution Plan Preview appears before detailed record list. | Consultant can explain what IDB will prepare in under 30 seconds. |
| Record preview | Record names are customer/product specific, not generic filler. | Consultant can point to exact Customer, Proof Item, and supporting records. |
| Write readiness | Create state is clear and safe. | Consultant sees `Create records locked`, exact write list, pilot gates, and confirmation phrase. |
| ROI summary | ROI most important is readable without opening every detail. | Consultant can state why the demo matters financially. |
| Competitive summary | NetSuite proof is industry-specific and safe. | Consultant can explain why NetSuite wins without unsupported competitor claims. |
| Run guidance | Live Controls are first and story copy is actionable. | Consultant can open, prove, handle objection, and close value from the drawer. |
| Trace/reset | Export and Clear all are obvious. | Consultant can export evidence and reset for the next prospect. |
| NetSuite coexistence | IDB does not block the consultant from using the NetSuite page. | This becomes the W18C adaptive workspace fit test. |

## Required Screenshots

- Plan after entering intake.
- Review first viewport.
- Review with Write Confirmation and Result visible.
- ROI / Competitive first viewport.
- Run first viewport.
- Trace/reset view.
- IDB expanded alongside a NetSuite transaction or customer page.

## Go / No-Go Questions

- Can a consultant run the intake without being trained on the tool?
- Can they explain the selected lane and proof anchor?
- Can they see exactly what records would be prepared?
- Can they value sell from ROI / Competitive without reading a wall of text?
- Can they run the live story without scrolling too much?
- Can they tell that creation is still locked?
- Can they export trace evidence and clear the session?

## No Regression

- No live writes.
- No automatic creation.
- No hidden SuiteScript submission.
- No unsupported competitor claims.
- No lane/proof/toggle changes.
- Transaction context remains gated until Customer and Proof Item result IDs and URLs exist.
